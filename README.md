# Тоны — тренажёр мандарина

Веб-приложение для отработки **тонов и пиньиня**. Работает целиком в браузере:
без бэкенда, без аккаунта, весь прогресс лежит локально.

Живая версия: https://tmiras257-lgtm.github.io/hanzi-trainer/

## Почему не написание иероглифов

Прежняя версия была тренажёром письма: иероглиф рисовался мышью в клетке 米字格,
каждая черта проверялась по форме и порядку. От этого отказались — письмо от руки
отрабатывается на бумаге, а трекпад для него неудобен настолько, что режим просто
не использовался. Программе досталось то, чего бумага не даёт: слух, тоны и голос.

Прогресс не потерян: карточки прежней колоды перенесены как карточки **чтения**,
интервалы повторений сохранились (`src/lib/db.ts`, миграция версии 1 → 2).

## Что внутри

**Четыре упражнения.**

| Упражнение | Что тренирует |
|---|---|
| Какой тон | Слушаешь слог, определяешь тон. Основа всего остального |
| Минимальные пары | Один слог в разных тонах: `mā` или `mǎ`. Самое тонкое различение |
| Произнести | Говоришь вслух, микрофон измеряет контур высоты голоса |
| Чтение иероглифа | Видишь иероглиф — выбираешь чтение. Без письма |

**Настоящий анализ тона, а не распознавание речи.** Прежняя версия проверяла
произношение через Web Speech API, который возвращает только текст: тон он не
разбирает, а ошибка в тоне обычно всё равно распознаётся как нужный иероглиф.
Теперь микрофон читается напрямую, а частота основного тона считается методом
McLeod (нормализованная разностная функция NSDF с параболическим уточнением,
`src/lib/pitch.ts`). Контур переводится в полутона относительно медианы записи и
сравнивается по форме с эталонами 55 / 35 / 214 / 51 — так что регистр голоса не
важен, важно движение. Звук никуда не отправляется, интернет не нужен.

Отказ микрофона разделён по причинам — нет доступа, нет устройства, не https, не
поддерживается — с конкретной подсказкой в каждом случае.

**Подбор материала.** Единица изучения — слог с тоном (`ma3`), а не иероглиф:
тон принадлежит слогу. Инвентарь из 528 тонированных слогов и 155 основ с
минимальными парами выводится из датасета на лету (`src/lib/syllables.ts`).
Неправильные варианты в вопросах не случайны: сначала тот же слог в другом тоне,
затем путаемые инициали (`zh/z/j`, `n/l`), затем финали (`-n/-ng`).

**Интервальные повторения.** SM-2 с двумя отклонениями: срыв роняет карточку до
интервала в 1 день, но не обнуляет ease factor; первые два успешных интервала
фиксированы (1 и 3 дня). Сессия держится в одном бюджете ответов, новый материал
занимает не больше 30%, а при накопившемся завале новые слоги не добавляются
вовсе — `src/lib/drill.ts`.

## Загрузка и шрифты

Китайский текст рендерится сабсетом Noto Sans SC, нарезанным ровно под те 1212
глифов, которые приложение способно показать: 1031 иероглиф плюс весь пиньинь с
диакритикой. **309 КБ вместо 17.8 МБ** полной гарнитуры. Шрифт предзагружается в
`<head>` и объявлен как `font-display: block`, поэтому подмены глифов на
системный шрифт не происходит ни на кадр.

```bash
npm run font     # пересобрать сабсет (скачивает исходный шрифт, ~18 МБ)
```

Сабсет закоммичен в `public/fonts/`, так что CI его не пересобирает. Исходный
шрифт — Noto Sans SC под SIL Open Font License 1.1; лицензия лежит рядом
(`public/fonts/OFL.txt`). Noto CJK собран из Adobe Source Han Sans, поэтому в
лицензии указано зарезервированное имя «Source» — оно не используется.

Экран загрузки — скелетон, повторяющий геометрию главной страницы, чтобы при
появлении данных ничего не сдвигалось.

## Цвет

Каждый тон держит один оттенок во всём интерфейсе. Палитра не подбиралась на
глаз: она проверена на разделимость при дальтонизме отдельно для тёмной и
светлой темы. Разделение попадает в допустимую полосу, поэтому цвет нигде не
кодирует тон в одиночку — рядом всегда стоит номер тона и пиньинь.

## Данные

800 самых частотных иероглифов из открытых источников (`npm run data`):

| Источник | Что берём | Лицензия |
|---|---|---|
| [hanziDB](https://github.com/ruddfawcett/hanziDB.csv) (список Jun Da) | ранг частотности, ключ, число черт | открытые данные |
| [makemeahanzi](https://github.com/skishore/makemeahanzi) | разложение на компоненты, этимология | LGPL / Arphic Public License |
| [complete-hsk-vocabulary](https://github.com/drkameleon/complete-hsk-vocabulary) | пиньинь, значения, уровни HSK 3.0, примеры слов | CC-BY-SA (данные CC-CEDICT) |

Значения первых 240 иероглифов переведены на русский вручную
(`scripts/ru-glosses.json`), дальше показываются английские глоссы.

## Локально

```bash
npm install
npm run dev          # http://localhost:5173/hanzi-trainer/
npm run build
npm run smoke        # SRS, планировщик сессии, инвентарь слогов
npm run tone-check   # разбор пиньиня, определение частоты, классификация тонов
npm run ui-check     # end-to-end в реальном Chrome + скриншоты обеих тем
```

`tone-check` проверяет движок на синтетике: частота определяется с точностью 3%
на 110–330 Гц, все четыре тона узнаются и на чистом контуре, и с дрожанием на
низком голосе, слишком короткая или тихая запись отклоняется.
